用户（2026-08-12）明确要求代码注释风格：**正常大白话，去除 AI 味**。写注释/命名时遵循。

**注释禁止**：
- 表情符号（⚠️ / ✅ / ❌ 等）
- 外部模组名称（mhzy / super-steve / omnimobs / fantasy 等）
- 行话术语（如"软判死"→用"判定死亡"这类大白话）
- 装饰性分隔线（═══ 等）

**命名规范**：
- 术语"梦幻"（FIRST_DREAM 伤害）已更名 **"涨跌多空"**（属性 modifier id `long_short`），代码注释用"涨跌多空"
- 标识符不得含外部模组缩写（如 `yizmodqzk$FE_GET_HEALTH_DATA` 已改 `yizmodqzk$HEALTH_DELTA`，"FE" 是外部模组缩写）

**代码不得针对其他模组**（用户强调"实际代码也不能去针对别的模组"）：
- 不得 `instanceof` 外部模组类、不得 `ModList.isLoaded()` 检测特定模组
- mixin / agent / 字节码注入目标必须通用（原版类或全实体），不点名任何外部类/方法/资源
- 兼容性处理用通用机制（按通道扫描/调用栈鉴权/命名无关），不做特定模组特判

**Why**: 用户认为注释里出现外部模组名、表情、AI 行话"显得很怪"；代码针对特定模组违反"全通用、不点名"的设计红线。

**How to apply**：
- 新写注释：简洁大白话描述机制本身，不引用外部来源或模组名
- 新命名：自解释的中性名（如 DREAM_ACCUM 等比累积），不用外部缩写
- 新增"兼容/防御/攻击"逻辑前自查：是否只对特定模组生效？是则改为通用机制
