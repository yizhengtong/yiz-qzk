# GUI 审美守则 — 积木化设计规范

> AI 拼装 GUI 时的视觉设计决策指南。技术正确 ≠ 好看。此文档解决"怎么摆才好看"。

---

## 核心原则

1. **每个槽位必须有身份** — 光板槽位堆在一起 = 看不清功能
2. **装饰不是多余的** — 特征图标（如 `smithing_table_feature.png`）是视觉锚点
3. **负空间是设计元素** — 槽位之间留白不够 = 拥挤 = 廉价感
4. **引导 > 说明书** — 用图标和布局暗示操作流程，而不是让玩家猜

---

## 一、纯容器型 GUI（箱子/仓库/背包扩展）

> 没有特殊功能，只是存放物品的格子阵列。

### 布局铁律

```
槽位间距：18px（固定）
列数：9 列（与玩家背包对齐）
行数：按需（3/4/5/6 行常见）
容器区上边距：≥ 一行空白（18px）
容器区下边距：≥ 半行空白（9px）
```

### 审美规则

**✅ 好看的做法：**

- 槽位阵列居中于内容区（水平方向自动对齐 9 列）
- 容器区和玩家背包之间的分隔条必须存在——它是视觉呼吸点
- 槽位行数 ≤ 6 时，上方留 18px 空白，下方留 9px 空白
- 槽位行数 > 6 时，上方留 9px 空白

**❌ 不好看的做法：**

- 槽位顶到边框（没有留白）
- 容器区和背包区紧贴（没有分隔条）
- 奇数行容器不用 9 列（破坏与背包的对齐感）

### 布局模板

```
3 行容器（标准箱子）→ 172×154
┌─────────────────────┐
│                     │  ← 9px 上留白
│  ░░ ░░ ░░ ░░ ░░ ░░  │
│  ░░ ░░ ░░ ░░ ░░ ░░  │  ← 3 行 × 18
│  ░░ ░░ ░░ ░░ ░░ ░░  │
│                     │  ← 9px 下留白
├────── split ────────┤
│   player_slots_9x4  │
└─────────────────────┘

6 行容器 → 172×208
```

## 二、工作方块型 GUI（锻造台/铁砧/工作台/酿造台）

> 有输入→输出的操作流程，需要引导玩家视线。

### 必须包含的元素

| 元素 | 作用 | 必要性 |
|------|------|:--:|
| **特征装饰图** | 视觉锚点，告诉玩家"这是 XX 台" | **必须** |
| **输入槽** | 放待处理物品 | **必须** |
| **输出槽** | 取成品 | **必须** |
| **引导图标** | 箭头/加号，暗示操作方向 | **强烈推荐** |
| **槽位标识图标** | 放在槽位内，提示"这里放什么" | **推荐** |

### 布局模式

#### 模式 A：水平流程（适合步骤较少的）

```
┌─────────────────────────┐
│                         │
│   [输入A] → [输入B]     │  ← 水平排列，箭头引导
│              ↓          │
│           [输出]        │
│                         │
├──────── split ──────────┤
│     player_slots_9x4    │
└─────────────────────────┘

适用：铁砧（两个输入 → 一个输出）
```

#### 模式 B：菱形/十字流程（适合多输入）

```
┌─────────────────────────┐
│                         │
│        [模板]           │  ← 上方
│                         │
│  [装备]  →  [输出]      │  ← 中间行，箭头指向输出
│                         │
│        [材料]           │  ← 下方
│                         │
├──────── split ──────────┤
│     player_slots_9x4    │
└─────────────────────────┘

适用：锻造台（三个输入 → 一个输出）
```

#### 模式 C：网格流程（适合工作台类）

```
┌─────────────────────────┐
│                         │
│   [ ] [ ] [ ]           │  ← 3×3 合成格
│   [ ] [ ] [ ]           │
│   [ ] [ ] [ ]           │
│             ↓           │
│          [输出]         │  ← 输出在右侧
│                         │
├──────── split ──────────┤
│     player_slots_9x4    │
└─────────────────────────┘

适用：工作台、合成台
```

### 特征装饰图的使用规则

1. **必须使用**对应工作方块的 feature 图（如 `smithing_table_feature.png`）
2. **放在容器区底层**，在槽位之下
3. **对齐方式**：如果 feature 图较小，居中对齐于容器区
4. **槽位位置必须与 feature 图上的槽位标记对齐**——feature 图上画了槽位边框的地方，实际槽位就要放在那里

### 审美规则

**✅ 好看的做法：**

- 特征装饰图 + 槽位叠加，形成"一体感"
- 引导箭头放在输入和输出之间，不遮盖槽位
- 输出槽用略微不同的视觉处理（如金色边框、高亮）
- 槽位标识图标用**半透明浅色**叠加在槽位内，不喧宾夺主

**❌ 不好看的做法：**

- 光板槽位堆叠，没有特征装饰图
- 输入和输出没有任何视觉区分
- 引导箭头过大或颜色过跳，比槽位还抢眼
- 槽位标识图标颜色太重，和槽位背景混在一起看不清

## 三、功能型 GUI（搜索/整理/排序/翻页）

> 带有交互控件（搜索框、排序按钮、翻页箭头）的 GUI。

### 搜索框

**位置**：容器区最上方，横跨内容区

```
┌─────────────────────────┐
│  [🔍 搜索...         ]  │  ← 搜索框，紧贴上边框
│                         │
│  列表/槽位内容区         │
│                         │
├──────── split ──────────┤
│     player_slots_9x4    │
└─────────────────────────┘
```

**审美规则**：
- 搜索框高 12px（使用 `search_box.png`），宽度 = 内容区宽度
- 搜索框上方不留白，紧贴顶边框
- 搜索框和下方内容区之间留 9px 间距

### 排序按钮

**位置**：搜索框右侧或列表顶部右侧

```
┌─────────────────────────┐
│  [🔍 搜索...    ▲ ▼]   │  ← 排序图标在搜索框内右侧
│                         │
│  排序列表内容            │
```

**审美规则**：
- `sort_up.png` / `sort_down.png` 放在搜索框内部右侧
- 两个图标之间留 2px 间距
- 如果无搜索框，排序图标放在列表区域右上角

### 翻页按钮

**位置**：列表底部，水平居中

```
│  列表内容               │
│                      ▲  │  ← 上翻页
│                      ▼  │  ← 下翻页
├──────── split ──────────┤
```

**审美规则**：
- 翻页按钮放在列表区和分隔条之间
- 左右翻页图标水平排列，上下翻页图标垂直排列
- 当前页码显示在翻页图标之间
- 翻页控件整体居中

### 确认/取消按钮

**位置**：容器区底部，分隔条上方

```
│  表单/设置内容          │
│                         │
│         [✓ 确认] [✕ 取消]│  ← 按钮行
├──────── split ──────────┤
```

**审美规则**：
- 确认在右，取消在左（符合 Windows/Mac 惯例）
- 按钮之间留 9px 间距
- 按钮行与分隔条之间留 9px 间距

## 四、输出槽的特殊处理

输出槽是工作方块 GUI 的终点，需要视觉突出。

### 常规做法

- 输出槽的背景边框用**略亮的颜色**（相对于普通槽位）
- 或者在输出槽旁边放置一个小小的 `result_arrow.png` 指向它

### 高级做法（推荐）

- 输出槽使用**略微放大的槽位纹理**（如果切了专用的输出槽图）
- 输出槽与输入槽之间保持**至少 36px（2 格）间距**，形成视觉隔离
- 引导箭头连接输入和输出，箭头的视觉重量在输出端加重

---

## 五、通用美观原则

### 留白标准

| 区域 | 最小留白 |
|------|:--:|
| 边框内上边距 | 9px |
| 边框内下边距 | 9px |
| 特征装饰图与边框之间 | 4px |
| 槽位行之间 | 0px（18px 间距已固定） |
| 功能按钮与内容之间 | 9px |
| 分隔条与上方内容 | 0px（紧贴） |
| 分隔条与下方背包 | 0px（紧贴） |

### 颜色使用原则

- 背景用 `fill_white.png` 的统一灰色——不要换色
- 功能性图标保留原色，不要统一染色
- 槽位标识图标用**半透明浅色**（alpha 150~200）
- 引导箭头保持 `result_arrow.png` / `process_plus.png` 原色

### 对齐原则

- 所有槽位列与玩家背包列对齐（9 列基准）
- 居中元素（标题、特征图、翻页控件）严格水平居中于内容区
- 左对齐元素（搜索框、列表）与左边框保持 BORDER+0 的起始位置

## 自检清单

生成 GUI 后，逐项确认：

- [ ] 有特征装饰图的工作方块 → 特征图已使用？
- [ ] 输入槽和输出槽 → 有视觉区分？
- [ ] 引导箭头 → 放在输入和输出之间？
- [ ] 槽位标识图标 → 颜色不过重、不喧宾夺主？
- [ ] 留白 → 边框内不少于 9px？
- [ ] 分隔条 → 存在且位置正确？
- [ ] 功能控件（搜索/排序/翻页）→ 位置符合上述规范？
- [ ] 整体比例 → 容器区不过矮（<54px）也不过矮胖或瘦长？
- [ ] 积木穷尽 → A/B/C 三区中可用的图都用上了？

## 六、非槽位型 GUI（天赋树/技能面板/状态页）

> 不是"放物品"的 GUI，而是"展示信息"的 GUI。布局逻辑完全不同。

### 与槽位型 GUI 的本质区别

| 槽位型 | 非槽位型 |
|--------|---------|
| 格子阵列 = 核心 | 信息区块 = 核心 |
| slot_default 铺网格 | slot_default 只用于"可交互节点" |
| 不需要装饰底纹 | **强烈建议加装饰底纹**（区分背景和内容） |
| 玩家背包必须 | 玩家背包可选（如果是纯信息面板可省略） |

### 布局模式：分区卡片式

```
┌── TL ──────── top_edge ──────── TR ──┐
│                                       │
│  ┌─ 顶部状态栏 ────────────────┐      │  ← 标题/点数/货币
│  │ 剩余天赋点: ★ 3            │      │
│  └────────────────────────────┘      │
│                                       │
│  ┌ 分类A ┐ ┌ 分类B ┐ ┌ 分类C ┐      │  ← 标签页
│                                       │
│  ┌── 主内容区 ──────────────────┐    │
│  │                              │    │
│  │  [节点]───[节点]───[节点]    │    │  ← 节点 + 连线
│  │    │                │        │    │
│  │  [节点]───[节点]    │        │    │
│  │            │        │        │    │
│  │          [节点]───[节点]     │    │
│  │                              │    │
│  └──────────────────────────────┘    │
│                                       │
│  ┌─ 详情面板 ──────────────────┐    │  ← 悬停/选中显示
│  │ 技能名称: XXX               │    │
│  │ 等级: 2/5 | 效果: +15% 伤害 │    │
│  └──────────────────────────────┘    │
│                                       │
├────────── split_bar ────────────────┤
│          player_slots_9x4            │  ← 按需添加
└── BL ───── bottom_edge ─────── BR ──┘
```

### 非槽位型 GUI 的积木三元分类

设计任何 GUI 前，先把所需积木分为三层：

```
第一层：已有可复用（A_通用 + B_功能中已有的）
  → 不用生成，直接引用

第二层：母模板填色（C_母模板 有模板，需 /api/fill 填色）
  → 需要生成，但有现成形状

第三层：从零创造（既无成品也无模板）
  → 需要全新绘制 / 从其他图裁剪
```

#### 以天赋界面为例

**第一层 — 已有**：
| 积木 | 来源 | 用途 |
|------|------|------|
| 全部边框 | A_通用 | 窗口框架 |
| `fill_white.png` | A_通用 | 背景填充 |
| `slot_default.png` | A_通用 | 节点底框 |
| `border_on.png` | A_通用 | 节点选中态 |
| `accept.png` | A_通用 | 确认按钮 |
| `cross_button.png` | A_通用 | 取消/重置 |

**第二层 — 母模板填色**：
| 母模板 | 填色方案 | 成品用途 |
|--------|---------|---------|
| `empty_slot_sword.png` | 金色 `#FFD700` | 战斗天赋节点图标 |
| `empty_slot_apple.png`(需先创建) | 绿色 `#4CAF50` | 生存天赋节点图标 |
| `empty_slot_enchantment.png`(需先创建) | 紫色 `#9C27B0` | 魔法天赋节点图标 |

**第三层 — 从零创造**：
| 新积木 | 尺寸 | 用途 |
|--------|:--:|------|
| `connector_h.png` | 18×2 | 水平连线 |
| `connector_v.png` | 2×18 | 垂直连线 |
| `talent_bg_pattern.png` | 16×16 | 天赋区装饰底纹 |
| `star_point.png` | 9×9 | 天赋点图标 |

### 积木穷尽法则

**生成 GUI 前，必须列出三元清单。** 原则：

- 第一层能用的**必须用**，不许漏
- 第二层有模板的**优先填色**，不要从零画
- 第三层才考虑全新创造
- 清单列完后问自己：**每个槽位/节点/区域都有对应的视觉标识吗？** 没有 = 缺积木

## 七、布局五法则（提炼自 Apple/Linear/Figma/Notion/Stripe）

### 法则 1：锚点法则
> 每个 GUI 内容区必须有一个视觉锚点。

- 工作方块 → 锚点 = 特征装饰图（`*_feature.png`）
- 纯容器 → 锚点 = 槽位阵列的整体轮廓
- 功能型 → 锚点 = 搜索框/主要交互控件
- 非槽位型 → 锚点 = 节点图/信息架构

### 法则 2：身份法则
> 光板槽位 = 未完成的 GUI。每个可交互区域都需要身份标识。

- 输入槽 → 放槽位标识图标（从 C_母模板 填色）
- 输出槽 → 边框高亮 + 箭头指向
- 功能按钮 → 图标 + 文字标签

### 法则 3：流程法则
> 有输入→输出的 GUI 必须用引导图标串联视觉流。

- `result_arrow.png` → 输入指向输出（水平流程）
- `process_plus.png` → 多材料合成（工作台）
- 节点连线 → 天赋/技能依赖关系

### 法则 4：留白法则
> 拥挤 = 廉价。每个功能区块之间必须有视觉分隔。

- 内容区与边框之间：≥ 9px
- 不同功能区块之间：≥ 9px
- 槽位行之间：固定 18px（不变）
- 特征装饰图与槽位之间：≥ 4px

### 法则 5：穷尽法则
> 已有的不用 = 浪费。每次生成前先检查 A/B/C 三区。

- A_通用：边框、槽位、填充、分隔条、进度条、确认/取消
- B_功能：特征装饰图、引导箭头、进度动画
- C_母模板：所有可填色的剪影模板

## 八、拼凑原则 — 从"贴图"到"布局"

> 此前的守则都在说"单张图怎么用"。本节说**多张图怎么拼成完整的 GUI**。

### 原则 1：先定区域，再填细节

不要先贴图再调大小。先画出布局框架：

```
┌── 标题区 ──────────────────┐  ← 固定高度
├── 内容区 ──────────────────┤  ← 可滚动/可扩展
├── split_bar ───────────────┤  ← 14px
├── player_slots ────────────┤  ← 76px
└────────────────────────────┘
```

**每个区域有明确的功能和高度**——标题区只放标题，内容区只放内容，不混在一起。

### 原则 2：内容区高度 ≠ 内容行数 × 行高

这是最容易犯错的地方。正确的做法：

```
❌ 错：容器高 = 4行 × 18px = 72px
    → 正好只能放下4行，没有呼吸空间

✅ 对：容器高 = 至少容纳所有内容 + 上下各 10~20px 留白
    → 即使只有4行，内容区底部也有留白
    → 后续加第5行时不会撑爆窗口
```

### 原则 3：标题区是"入口"，不是"占位符"

标题区应该包含：
- 分类图标（大图标 32×32）
- 标签页导航（如果有多类内容）
- 属性/状态摘要（如适用）

标题区高度通常 40~60px（含图标+标签页），不要压缩到 20px 以下。

### 原则 4：节点/条目行高 = 内容 + 间距

每行/每个节点占用的垂直空间：

```
最小：18px（纯 slot，仅图标）
推荐：22~26px（slot + 描述文本 + 状态标记）
舒适：30~36px（slot + 描述 + 等级条 + 操作按钮）
```

**宁大勿小**：间距多了眼睛不累，少了视觉拥挤。

### 原则 5：可滚动 > 固定

当内容行数不确定时：
- 内容区高度设为一个固定值（如 120~160px）
- 实际内容超出时滚动
- 内容少时内容区底部留白

```
┌── 内容区 ──────────────────┐  ← 固定高度 140px
│  [节点1]                    │
│  [节点2]                    │
│  [节点3]                    │  ← 只有3行时，底部自然留白
│                             │
│            （留白）          │
└─────────────────────────────┘
```

### 原则 6：用 512×512 的视野思考

参考 GUI 是 512×512，窗口宽松、信息分层清晰。这与 172×154 的标准箱子 GUI 是两种设计理念：

| 维度 | 标准容器（A_通用风格） | 功能面板（参考风格） |
|------|---------------------|-------------------|
| 窗口大小 | 172×154~172×208 | 256×256 ~ 512×512 |
| 内容密度 | 高（槽位紧密排列） | 低（图标+文本+留白） |
| 滚动 | 不分页，槽位固定 | 内容区可滚动 |
| 适用场景 | 背包/箱子/容器 | 天赋/属性/设置/教程 |

判断用哪种风格：**如果是功能型/非槽位型 GUI，用宽松布局；如果是容器型，用紧凑布局。**
