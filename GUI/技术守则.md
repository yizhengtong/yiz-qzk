## 1. 原件保护守则（不可变）

GUI 纹理原件严禁直接修改。使用时必须**复制到工作目录**操作。

- 禁止移动、删除、重命名原件
- 禁止修改原件的像素内容
- 所有裁剪/填色/拼接在副本上进行

> 原件目录：`description/` 和 `Tools Container GUI/`（历史保留）
> 工作目录：`A_通用/` 和 `B_功能/`

## 2. 1px 偏移（最高优先级）

**所有槽位背景纹理绘制起点 = slot.x - 1，slot.y - 1**

原因：Minecraft `AbstractContainerScreen.isHovering()` 的命中盒起点是 `(slot.x - 1, slot.y - 1)`，不是 `(slot.x, slot.y)`。这是引擎级设计决定，不可"修复"，只能遵守。

```
命中检测范围 = (slot.x-1, slot.y-1) ~ (slot.x+17, slot.y+17)
纹理绘制起点 = leftPos + slot.x - 1
物品渲染起点 = leftPos + slot.x           （物品 16×16，居中于 18×18 槽位内）
```

代码：
```java
// 标准槽位
blit(TEX_SLOT, x + BORDER + col * SLOT - 1, y + row * SLOT - 1, 18, 18);

// 玩家背包整块
blit(TEX_SLOTS, x + BORDER - 1, invY - 1, 162, 76);
```

## 3. 窗口尺寸计算公式

```
SLOT   = 18     // 槽位间距
BORDER = 5      // 边框厚度

总宽度  = BORDER × 2 + COLS × 18
总高度  = BORDER × 2 + 容器行数 × 18 + 分隔条(14) + 玩家背包(76)
```

标准 9 列布局（以 3 行箱子为例）：
```
┌── TL ── top_edge ── TR ──┐  ← 5px 上边框
│  ░░ ░░ ░░ ░░ ░░ ░░ ░░ ░░ ░░  │  ← 3行 × 18px  容器槽区
├───────── split_bar ────────┤  ← 14px 分隔条
│       player_slots_9x4      │  ← 76px 玩家背包
└── BL ── bottom_edge ── BR ┘  ← 5px 下边框
总窗口 172×154（9 列 3 行标准）
```

## 4. 大容器变列算法

格数 > 27（3×9）时，不再固定 9 列。在 [9, 16] 列范围内求最优列数：

```
for cols in 9..16:
    rows = ceil(N / cols)
    ratio = max(cols, rows) / min(cols, rows)
选 ratio 最接近 1 的组合
```

关键值速查：

| 格数 | 最优方案 | 窗口尺寸 |
|------|---------|---------|
| ≤27 | 9×3 | 172×154 |
| 54 | 9×6 | 172×208 |
| 100 | 10×10 | 190×274 |
| 128 | 12×11 | 226×298 |
| 200 | 14×15 | 262×352 |
| 300 | 16×19 | 298×436 |

## 5. 玩家背包居中规则

当容器列数 > 9 时，底部玩家背包（固定 162px 宽）在内容区水平居中：

```
invOffset = (COLS - 9) × 18 / 2
背包绘制起点 x = leftPos + BORDER + invOffset - 1
```

```java
// 容器槽位：占满内容区宽度
addSlot(new Slot(chestInv, index, BORDER + col * SLOT, BORDER + row * SLOT));

// 玩家背包：居中偏移
int invOffset = (COLS - 9) * SLOT / 2;
addSlot(new Slot(playerInv, i, BORDER + invOffset + col * SLOT, PLAYER_INV_Y + row * SLOT));
```

## 7. renderBg 勿重复调用

`AbstractContainerScreen.render()` 内部已调用 `renderBg()`。

```java
// ✅ 正确：只 override renderBg
@Override
protected void renderBg(GuiGraphics g, float delta, int mx, int my) {
    // 只画背景
}

// ❌ 错误：render() 里又手动调 renderBg() → 双重绘制 + 渲染错乱
```

## 8. Screen ↔ Menu 坐标对齐

Menu 的 `addSlot()` 坐标必须和 Screen 的 `blit()` 坐标**严格一致**。

```java
// Screen — 定义布局常量
private static final int SLOT_Y = 45;
blit(TEX_SLOT, x + BORDER + col * SLOT - 1, y + SLOT_Y - 1, 18, 18);

// Menu — 使用同一个常量
addSlot(new Slot(container, 0, BORDER + col * SLOT, SLOT_Y));
```

不一致的后果：1px 偏移规则失效，点击检测错位。

## 9. 容器点击修复（containerId）

直接 `mc.setScreen()` 的容器 `containerId = -1`，服务端丢弃所有点击。

单机模式修复：
```java
if (server != null) {
    ServerPlayer sp = server.getPlayerList().getPlayer(mc.player.getUUID());
    if (sp != null) {
        sp.openMenu(new SimpleMenuProvider(
            (id, inv, p) -> new MyMenu(id, inv),
            Component.literal("Title")
        ));
    }
}
```
